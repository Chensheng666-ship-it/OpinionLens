# 舆见 OpinionLens · 从零安装与启动（实测版）

> 本文记录「一台干净的 Windows 10/11」从零装到「窗口右上角显示 **本地服务 在线**」的完整步骤。
> 命令均在 **PowerShell（建议 7.x）** 中执行，工作目录为仓库根目录（例如 `D:\OpinionLens`）。
> 文末列出三个 README 未覆盖、实测必踩的坑。

---

## 0. 一句话回答「MediaCrawler 装在哪」

采集引擎装在 **仓库根目录下的 `MediaCrawler\`**，由 `scripts\setup_mediacrawler.ps1` 自动克隆（固定 commit
`b059657a872614bc0cb887af801b753ff4587d12`）并用 `uv sync` 建虚拟环境：

```text
D:\OpinionLens\
├─ MediaCrawler\                 ← 采集引擎（第三方，不随本仓库分发）
│  └─ .venv\Scripts\python.exe   ← 引擎 + sidecar 共用的 Python 解释器
├─ app\
└─ scripts\setup_mediacrawler.ps1
```

**这个名字和位置是硬编码的，不能改也不能挪**：

| 位置 | 代码依据 |
|---|---|
| `app/scripts/dev.ps1:7` | `$python = Join-Path $project 'MediaCrawler\.venv\Scripts\python.exe'` |
| `app/scripts/run_sidecar.ps1:6` | 同上 |
| `app/desktop/main.js:47` | 缺省 `join(PROJECT_DIR,'MediaCrawler','.venv','Scripts','python.exe')`（可用 `MC_PYTHON` 覆盖） |
| `app/engine/entry.py` | `MC_ROOT` 默认 `<project>/MediaCrawler`（可用环境变量 `MC_ROOT` 覆盖） |

也就是说：MediaCrawler 的 `.venv` **同时是 sidecar 的运行时**。它没装好，界面能开但「服务在线」永远不来。

## 1. 前置依赖

| 依赖 | 版本 | 检查命令 | 说明 |
|---|---|---|---|
| Node.js | 20+ | `node -v` | 安装 Electron 与打包链 |
| uv | 最新 | `uv --version` | 装引擎的 Python 环境；`uv` 会自动下载 CPython 3.11 |
| Git | 任意 | `git --version` | 克隆引擎 |
| Edge | 系统自带 | — | Playwright 走 `channel=msedge`，**不用** `playwright install chromium` |
| 磁盘 | ~1.5 GB | — | 引擎 venv ≈ 480 MB，node_modules ≈ 300 MB |

安装 uv（二选一）：

```powershell
winget install --id astral-sh.uv -e
# 或
irm https://astral.sh/uv/install.ps1 | iex
```

装完 **必须重开一个终端**（winget 只改了 PATH），否则 `setup_mediacrawler.ps1` 会报「未找到 uv」。

## 2. 装采集引擎

```powershell
cd D:\OpinionLens
.\scripts\setup_mediacrawler.ps1
```

脚本做三件事：`git clone --no-checkout` → `git checkout <固定commit>` → `uv sync`（首次 3–5 分钟）。

### 坑 A：`uv sync` 报 403（清华源）

上游 `MediaCrawler/pyproject.toml` 把默认索引钉死成清华源：

```toml
[[tool.uv.index]]
url = "https://pypi.tuna.tsinghua.edu.cn/simple"
default = true
```

实测该源对部分 wheel 返回 **403 Forbidden**（`pygments==2.19.2`、`fonttools==4.58.4` 等）。
**0.3.0 起脚本会自动改用备用索引重试**（阿里云 → PyPI 官方，见 `-FallbackIndexes`），
并在结尾打印最终使用的索引；三条索引都失败时才会抛错，此时手动执行：

```powershell
cd MediaCrawler
uv sync --default-index https://mirrors.aliyun.com/pypi/simple
# 备选：https://pypi.org/simple / https://mirrors.ustc.edu.cn/pypi/simple
```

校验：

```powershell
& D:\OpinionLens\MediaCrawler\.venv\Scripts\python.exe -c "import playwright, httpx, pandas, openpyxl, fastapi, uvicorn, jieba, sqlalchemy, PIL; print('engine+sidecar deps OK')"
& D:\OpinionLens\MediaCrawler\.venv\Scripts\python.exe --version   # 期望 3.11.x
```

## 3. 装界面依赖

```powershell
cd D:\OpinionLens\app\desktop
npm install
```

仓库自带 `app/desktop/.npmrc`（registry 与 electron_mirror 走 npmmirror），国内网络无需额外配置。

### 坑 B：`npm install` 成功但 Electron 本体没下下来

`npm install` 报 `added 283 packages` 后，`node_modules\electron\dist\electron.exe` **可能不存在**
（postinstall 静默跳过）。此时 `dev.ps1` 的检查会通过（`node_modules\.bin\electron.cmd` 在），
但启动时报「Electron failed to install correctly」。手动补一次即可：

```powershell
cd D:\OpinionLens\app\desktop
$env:ELECTRON_MIRROR = 'https://npmmirror.com/mirrors/electron/'
node .\node_modules\electron\install.js
Test-Path .\node_modules\electron\dist\electron.exe    # 期望 True
```

## 4. 启动

```powershell
cd D:\OpinionLens
.\app\scripts\dev.ps1
```

Electron 会自动拉起 Python sidecar（随机端口 + 随机 token，只绑 `127.0.0.1`）。
**判定成功的三条硬证据**（任一即可）：

1. 窗口右上角显示绿色 **本地服务 在线**；
2. `app\data\logs\main.log` 出现 `sidecar 就绪：http://127.0.0.1:<port>（pid=…）`；
3. `Get-Process electron` 有窗口标题为 `舆见 OpinionLens` 的进程。

数据目录：源码运行 `D:\OpinionLens\app\data\`；安装版 `%APPDATA%\OpinionLens\`。

### 坑 C：窗口一闪而过

最常见不是崩溃，而是 **已有实例在跑**（Electron 单实例锁）。先结束残留进程再启动：

```powershell
Get-Process electron,OpinionLens -ErrorAction SilentlyContinue | Stop-Process -Force
```

其它排查入口：`app\data\logs\main.log`（主进程）、`app\data\logs\sidecar.log`（Python 服务）。
若报 Chromium 沙箱/GPU 崩溃（`GPU process launch failed: error_code=18`，常见于远程桌面/EDR），
`dev.ps1` 默认已启用兼容模式；想强制严格沙箱设 `$env:FS_ELECTRON_SANDBOX='1'`。

## 6. 环境自检（可选，离线）

```powershell
cd D:\OpinionLens
.\app\scripts\selftest.ps1
```

覆盖 engine patch / exporter / sidecar 全链路 / 报告管线 / Electron 截图。

### 已知历史差异（0.3.0 已修）

0.3.0 之前，本机跑自测会稳定出现 1 项 FAIL，失败点在：

```text
tests\python\selftest.py  _craft_interrupted_run(data_dir)
app\sidecar\state.py     self._conn.execute("PRAGMA journal_mode=WAL")
sqlite3.OperationalError: disk I/O error
```

时序是：`sidecar.stop()` 用 `taskkill /F /T` 强杀进程树后**立刻**用新连接把同一个 WAL 库切到 WAL 模式。
Windows 下强杀后 `-wal/-shm` 的句柄与 SHM 映射释放有延迟，这一步会拿到 `SQLITE_IOERR`。
证据：同一份 `app.db` 事后单独打开完全正常（`journal_mode=wal`、`PRAGMA integrity_check=ok`），
加 0.2–1 s 再开也不复现；**只影响这条断言，不影响运行时功能**。

0.3.0 已在 `_craft_interrupted_run()` 中对建连加了 5 次退避重试（仅测试代码），自测应全绿。
若仍出现同类 `disk I/O error`，先看是否有杀毒/加密盘过滤驱动在扫 `%TEMP%`，再考虑加大重试次数。

## 7. 版本号：只有一个来源

`app/desktop/package.json` 的 `version` 是唯一来源。主进程 `app.getVersion()` 通过 `FS_APP_VERSION`
注入 sidecar，sidecar 的 `app/sidecar/version.py` 优先读它、缺失时回退 `FALLBACK_VERSION`；
`engine_runner.SIDECAR_VERSION`、`report_data.APP_VERSION`、`/api/system` 回报的版本都引用同一模块。
渲染层 `app.js` 的 `FS.APP_VERSION` 只是静态预览兜底。

改版本号的正确顺序：

1. `app/desktop/package.json` 与 `package-lock.json` 的 `version`；
2. `app/sidecar/version.py` 的 `FALLBACK_VERSION`（离线自测会断言两者相等，不等就红）；
3. `README.md` 徽章 + `CHANGELOG.md` 新条目。

> 历史遗留：0.2.x 时期界面显示 `v0.6.0`（sidecar 硬编码）、报告管线写 `0.3.0`、渲染层兜底 `0.1.0`，
> 三个值互不相同；0.3.0 起统一。

## 8. 一页速查

```powershell
# 首次安装
winget install --id astral-sh.uv -e            # 然后重开终端
git clone https://github.com/SolitudeZY/OpinionLens.git D:\OpinionLens
cd D:\OpinionLens
.\scripts\setup_mediacrawler.ps1               # 403 会自动换索引重试（见「坑 A」）
cd app\desktop; npm install; node .\node_modules\electron\install.js   # 见「坑 B」
cd ..\..

# 每次启动
cd D:\OpinionLens
.\app\scripts\dev.ps1

# 自测 / 单跑 sidecar / 只开 UI
.\app\scripts\selftest.ps1
.\app\scripts\run_sidecar.ps1                  # token=devtoken，便于 curl
cd app\desktop; npm run start:no-sidecar
```
