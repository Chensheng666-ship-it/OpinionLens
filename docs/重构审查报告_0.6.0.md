## 5. 未做 / 遗留（4 项，均不影响当前发布）

| 项 | 现状 | 为什么没做 | 建议 |
|---|---|---|---|
| **P0-3 `except Exception` 分层 + ruff BLE001** | 仍有约 290 处 `except Exception`（多为边界层兜底）；`patches.py` 的静默吞错已归零 | 需要在 CI 里逐步收紧规则 + 大量人工判断哪些是"边界层" | 加 `ruff` 并只对 `app/engine/adapters/`、`app/sidecar/runner/` 开 BLE001，其余白名单，逐步扩 |
| **P1-4 平台元数据单一来源** | 平台 id/标签仍分散在 `PLATFORM_LABELS`、`FS.PLATFORMS`、CSS 类名、preview mock | 属纯整理，改动面广（前端+后端+mock），收益低于重构主线 | 抽 `platforms.json`，后端读它、前端构建期内联 |
| **P1-5 `styles.css` 单文件 2087 行** | 未拆 | 纯风格问题，无功能收益 | 按 theme/base/components/views 拆四文件 |
| **JS 类型检查（tsc --checkJs）** | 未做（只 `node --check` 语法） | 需要引入 TypeScript 且现有 2.6 万行 JS 的 JSDoc 覆盖不足，首轮会报几百条 | 先只对 `update.js` / `ui-kit.js` / `api.js` 开 `// @ts-check` |

另有两条**已知边界**（非缺陷，已写进 CONTRACT）：

- `feed.seq` 是"数据集内位次"：某条内容被重采集会拿到更大的 seq 并以"新条目"回传（前端按 `(platform,id)` 去重兜住）；
- 内存日志行号（环形缓冲）与 sidecar 重启后的文件行号是两套编号，重启且页面不刷新时可能错位（客户端遇错回退全量）。

## 7. 审查时可能想反问的几个点（我先给答案）

| 疑问 | 回答 |
|---|---|
| 为什么不直接删掉 `engine_runner.py` 而留门面？ | 20+ 处 `from engine_runner import X`（`main.py`/`api_*`/`report_manager`/4 个测试文件），门面让重构对调用方零影响；门面完整性有 `getattr` 断言守 |

## 8. 复跑失败时怎么定位

| 现象 | 先看这里 |
|---|---|
| `ENGINE_INCOMPATIBLE: 缺失 N 个必需符号` | 上游 commit 变了：`git -C MediaCrawler rev-parse HEAD` 应等于 `b059657a872614bc0cb887af801b753ff4587d12` |
| e2e 超时/Cdp 目标未就绪 | 是否已有应用实例占用单实例锁（`Get-Process electron`），脚本会打印 electron stdout 尾部 |
| 安装包 verify 截图超时 | 同上；另看 `%APPDATA%\OpinionLens\logs\main.log`（脚本已自动附带尾部日志） |
| `EXPORT_SCHEMA_MISMATCH` | 旧库缺列：看返回的 `schema.missing_required`；需要硬失败才传 `strict_schema=True` |
| `REPORT_PACKAGE_INVALID` | 看返回的字段路径（如 `counts.total`） |
