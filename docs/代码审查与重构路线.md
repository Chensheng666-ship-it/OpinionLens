## 1. P0：先解决「会断」和「会静默出错」的地方

### P0-1 `patches.py` 的补丁面过于脆弱（2617 行 / 7 个 patch / 40 处 `setattr`）

现状：所有平台适配都靠 monkeypatch 直接改上游内部函数（`patch_user_hash`、`patch_browser_channel`、
`patch_kuaishou_search`、`patch_weibo_comment_empty`、`patch_login_only`、`patch_login_blocked`、
`patch_douyin_login_dialog`），并且有 23 处异常被静默吞掉。

风险：
- 上游换实现/改名 → 补丁"打了个空枪"，**不报错**，表现为「采不到数据但显示完成」；
- 静默 `pass` 让登录态、二维码、评论抓取的失败被掩盖。

改法（同时是最大的重写机会）：
1. 拆成 `app/engine/adapters/<platform>.py`，每个适配器声明它依赖的上游符号清单；
2. 启动时做一次 **上游契约探测**：符号缺失 → 直接 `ENGINE_INCOMPATIBLE(上游版本不匹配: xhs.notes)`，
   而不是继续跑；
3. 补丁内异常统一 `raise EnginePatchError(platform, patch_name, detail)`，由出口层转成
   `progress` 事件的 `error` 级别（用户看得到，selftest 也能断言）；
4. 为每个适配器加一个「上游契约快照测试」：固定 MediaCrawler commit 跑一遍，断言入口函数存在 + 行为签名一致。

收益：从「升级上游靠祈祷」变成「升级上游先跑契约测试」。

### P0-2 `engine_runner.py` 上帝模块（3187 行 / 12 类 / 120 方法）

现状：`SidecarConfig`、`EngineRunner`、`ActivityGuard`、`LoginManager`、`RunManager`、`RunRuntime`、
`EngineService` 等挤在一个文件里；`RunManager` 既管选号、又管重试、又管事件、又管配额记账。

风险：任何改动都要读 3000 行；无法单测（只能整链路集成测，一次 3 分钟）。

改法：
| 拆出模块 | 内容 |
|---|---|
| `runner/process.py` | PTY/子进程、stdout 解析、进程树回收 |
| `runner/login.py` | 登录会话状态机（starting→waiting_qr→…） |
| `runner/run.py` | 采集编排、重试策略、换号决策（依赖注入 `AccountPicker`） |
| `runner/feed.py` | 事件流聚合、feed/log tail |
| `runner/service.py` | 对外门面（HTTP 层只依赖它） |

配套：给 `RunManager` 定义 `CrawlBackend` 协议（`start/stop/on_event`），用 fake backend 写单测。

### P0-3 297 处 `except Exception`

现状：绝大部分是"出口层兜底"，这没问题；问题在**内层**也照抄同一种写法（尤其 `patches.py` 23 处）。

改法：立一条团队约定并落到 lint——
- **边界层**（HTTP handler、子进程读取、UI 回调）：允许 `except Exception`，但必须 `log.exception` + 上报事件；
- **业务层**（选号、配额、导出、报告）：只捕获具体异常，否则上抛；
- **补丁层**：不允许静默，必须转成显式错误。

落地方式：`ruff` 规则 `BLE001`（禁止裸 `except Exception`）在白名单外全量开启，逐步收紧。

### P0-4 前端把 112 KB mock 打进主包

现状：`preview.js` 2117 行假数据，随主包一起加载（首屏要解析它）。

改法：改成按需加载——`FS.mode === 'preview'` 时才 `import('./preview.js')`；正式运行时零成本。
顺带把 mock 与真实类型对齐（现在 mock 字段是手写的，容易和 sidecar 契约漂移）。

## 2. P1：可维护性与一致性的账

### P1-1 `report_data.py` 三合一（1404 行）
读库 + 统计 + 情感批处理 + 数据包组装全在一个文件。建议拆 `dataset.py`（SQL→NormalizedDataset）、
`package.py`（数据包 v1 组装 + schema 校验）、`sentiment.py`（批处理/缓存/兜底）。数据包用 `TypedDict`
或 pydantic 建模，`public-sentiment-data@v1` 的字段就有编译期保障。

### P1-2 `exporter.py` 命令式写表（865 行）
每张表的列都是手写 `ws.append([...])`。改成**声明式列规格**：

```python
SHEET_SPECS = [
    SheetSpec("概览", [Col("指标", "metric"), Col("数值", "value")], rows=overview_rows),
    SheetSpec("小红书内容", CONTENT_COLS, rows=content_rows("xhs")),
    ...
]
```

好处：加平台/加字段只改规格表；可在导出前做「规格列 vs DB 列」一致性断言（避免静默导出空列）。

### P1-3 前端重复工具函数
`apiErrNote / numOr / strOr / chip / bannerHtml` 在 `settings.js`（8 个）与 `accounts.js`（3 个）各写一份。
抽 `renderer/ui-kit.js`（`FS.ui.*`），两个页面改为引用；顺带统一 toast/错误文案口径。

### P1-4 平台元数据单一来源
平台 id/中文名/图标/排序散在 `account_manager.PLATFORM_LABELS`、`FS.PLATFORMS`、CSS 类名、mock 里。
建议一份 `platforms.json`（id/label/icon/tileColor），Python 与前端各自读取（前端可构建期内联）。

### P1-5 `styles.css` 单文件 2087 行
按 `theme / base / components / views` 拆四个文件，用现有 CSS 变量串起来；改动成本低、review 更清晰。

## 3. P2：体验与工程化

| 项 | 现状 | 建议 |
|---|---|---|
| 采集动态轮询 | 前端固定 1.5s 拉 `/feed` 全量 | 改为 `since_seq` 增量（后端事件总线已有 seq） |
| 日志 tail | 内存保留 5000 行 + 每次全量返回 | 环形缓冲 + `after_line` 增量 |
| 安装包体积 | 237 MB（便携 Python 637 MB staging） | 用 python-build-standalone 精简，剔除未用 stdlib/包；目标 ≤170 MB |
| 端到端测试 | CDP 脚本是一次性的，未入库 | 固化为 `app/scripts/e2e/`（采集/更新/数据目录三条主链路）+ CI |
| 类型检查 | 无 | 新代码开 `mypy --strict` 子集；前端加 `tsc --checkJs`（JSDoc 已有一半） |
| 定时器管理 | `accounts.js` 3 个 interval / 9 处 clear（不配对的风险） | 统一 `FS.timers.track()`，`destroy()` 一次性清理 |
